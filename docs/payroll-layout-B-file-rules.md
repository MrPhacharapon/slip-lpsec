# กติกา PDF สลิปเงินเดือนรูปแบบ B ที่ตรวจรับแล้ว — Branch ทดสอบ

เอกสารฉบับนี้เป็นรายละเอียดล่าสุดของกติกา B และใช้แทนคำอธิบายแบบย่อที่อาจระบุเพียงว่า “1–2 สลิปต่อหน้า” ในเอกสารเก่า

## รูปแบบที่ยอมรับ

- **A:** ทุกหน้าเป็นสลิปบุคลากรหนึ่งคน พร้อมหัวเอกสารหนึ่งชุด
- **B:** ทุกหน้าเป็นสลิปสองคน (หัวเอกสารสองชุด) **ยกเว้นหน้าสุดท้าย** ที่เป็นสลิปหนึ่งคนได้ เมื่อจำนวนบุคลากรเป็นเลขคี่
- **ปฏิเสธ:** A ตามด้วย B, สลิปหนึ่งคนแทรกกลาง B, มีหน้า B สองคนหลังหน้าเดี่ยว หรือมีหน้าเดี่ยวมากกว่าหนึ่งหน้าใน B
- เมื่อพบความผิดรูปแบบหรือการระบุเจ้าของไม่ครบ ต้องหยุดก่อนสร้าง PDF รายบุคคลและก่อนมีการเขียนฐานข้อมูลทั้งหมด
- ตรวจชื่อ–นามสกุล เลขบัญชี 10 หลัก และเลขตำแหน่ง 7 หลักตามทะเบียนในการอัปโหลดของผู้ดูแลเท่านั้น
- **หน้าเว็บบุคลากรคงการค้นหาจากเลขบัญชี 10 หลักตามข้อตกลงเวอร์ชันนี้ ไม่เพิ่ม OTP หรือบัญชีผู้ใช้บุคลากร**

## การบังคับใช้กติกาในโค้ด

- `src/lib/slip-validation.ts` — `assertSlipDocumentLayout` ตรวจรูปแบบทั้งเอกสารและระบุหน้าที่ผิด
- `src/app/admin/page.tsx` — ตรวจเงื่อนไขก่อน rasterize และก่อน Stage/Publish
- `scripts/validate-private-payroll-pdfs.mjs` — ใช้กติกาเดียวกันใน PDF.js CLI ส่วนตัว
- `tests/slip-validation.test.mjs`, `tests/private-payroll-pdf-fixtures.e2e.mjs`, `tests/payroll-layout-document-flow.test.mjs` — ทดสอบกติกา, PDF.js จำลอง และลำดับการเรียกใช้งาน

**ขอบเขต:** CI กับ PDF สมมติไม่ใช่การตรวจรับไฟล์เงินจริงด้วย PDF.js; Supabase Test ที่ใช้ Credentials จริงและการ Restore Backup Production จริงยังต้องตรวจแยกกันก่อนอนุมัติ Production

ไม่มีข้อมูลบุคลากรหรือ PDF เงินเดือนจริงในเอกสารนี้
