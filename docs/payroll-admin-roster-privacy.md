# การใช้ทะเบียนบุคลากรเพื่อแยกสลิป — Branch ทดสอบ

## เหตุผลของการเปลี่ยนแปลง

ก่อนหน้านี้ หน้า Admin ดาวน์โหลด CSV ของทะเบียนผ่านลิงก์ Google Sheets ที่เบราว์เซอร์อ่านโดยตรง และรองรับตัวแปร `NEXT_PUBLIC_STAFF_SHEET_URL` ที่อาจทำให้ตำแหน่งไฟล์ทะเบียนรั่วผ่าน client bundle

ตอนนี้หน้า Admin รองรับแหล่งข้อมูลสองแบบ:

1. **เลือก CSV จากเครื่องของ Admin** ก่อนอัปโหลด PDF ในครั้งนั้น ข้อมูลต้นฉบับ CSV ถูกอ่านและตรวจในเบราว์เซอร์ที่มีสิทธิ์ Admin เท่านั้น **ไม่มีการอัปโหลดตัวไฟล์ CSV ต้นฉบับ** หรือจัดเก็บทะเบียนไว้บนเซิร์ฟเวอร์; แต่รายการสลิปที่ผ่านการจับคู่แล้วจะส่งชื่อและเลขบัญชีที่จำเป็นไปยัง API เพื่อบันทึกสลิปตามการทำงานปกติ
2. **ไม่เลือก CSV:** หน้า Admin เรียก `GET /api/admin/roster` ซึ่งตรวจคุกกี้ Admin แล้วเซิร์ฟเวอร์จึงอ่าน Spreadsheet ID จาก `STAFF_SHEET_ID` (server-only) เพื่อดึงข้อมูลและตรวจชื่อ–เลขบัญชี–เลขตำแหน่ง ก่อนส่งให้ Admin; ผู้ใช้ทั่วไปเรียก API นี้ไม่ได้

ทั้งสองแบบใช้กติกา `parseRoster` เดิม: ชื่อคอลัมน์ที่ 1, เลขบัญชี 10 หลักที่คอลัมน์ที่ 3, เลขตำแหน่ง 7 หลักที่คอลัมน์ที่ 4 และรักษาศูนย์นำหน้า ไม่มีการอนุญาตข้อมูลซ้ำหรือเดาเจ้าของจากลำดับแถว

**ตัวเลือก CSV ส่วนตัวเหมาะสำหรับทะเบียนที่ไม่ควรเปิดการแชร์บนอินเทอร์เน็ต** ผู้ดูแลควรส่งออก CSV UTF-8 จากแหล่งที่มีสิทธิ์ เข้ารหัสหรือเก็บในเครื่องที่ได้รับอนุญาต และไม่ส่งไฟล์ทะเบียนไป GitHub, CI, สาธารณะ หรือแชท

## เงื่อนไขสำคัญของ Google Sheets

การย้าย URL จากเบราว์เซอร์มาเซิร์ฟเวอร์ **ไม่ได้เปลี่ยนสิทธิ์การแชร์ของ Google Sheet ต้นทาง** หากเลือกแบบที่ 2 และการดาวน์โหลด Google CSV ไม่ได้รับสิทธิ์ ระบบจะปฏิเสธและไม่อัปโหลดสลิป Google Sheet ที่ยังเปิดแบบ Anyone with the link อาจถูกเข้าถึงได้โดยผู้ที่ทราบลิงก์อยู่แล้ว

หากต้องการเก็บ Google Sheet เป็น Private และยังอ่านอัตโนมัติบนเซิร์ฟเวอร์ ต้องเพิ่มการยืนยันตัวตนระหว่างเซิร์ฟเวอร์กับ Google Sheets (เช่น service account) ที่ได้รับอนุญาตและตรวจรับ **ซึ่งยังไม่ได้พัฒนาในเวอร์ชันนี้** ทางเลือกที่ไม่เพิ่ม Credentials คือเลือกไฟล์ CSV ส่วนตัวจากเครื่อง Admin

## การตรวจรับและข้อจำกัด

- ต้องผ่าน Unit Tests และ Browser E2E ที่บล็อกการดาวน์โหลดทะเบียนตรงจากเบราว์เซอร์
- ทดสอบกรณีบุคคลทั่วไปเรียก `/api/admin/roster` ต้องได้ 401
- ทดสอบกรณี `STAFF_DIRECTORY_DISABLED=true` บน Test ต้องไม่อ่าน Google Sheets
- ทดสอบผู้ดูแลเลือก CSV ถูกต้อง, CSV ขนาดใหญ่/รูปแบบผิด, และ PDF ที่ชื่อ/บัญชี/เลขตำแหน่งไม่ตรงทะเบียน ให้ไม่เกิดการเขียนข้อมูล
- **Production ยัง NO-GO** จนกว่า Test-only Integration, PDF.js กับ PDF จริง, Backup/Restore, ACL/RLS/Private Storage และ Secret/Deployment Cutover จะผ่าน

หน้าเว็บบุคลากรยังค้นหาสลิปด้วยเลขบัญชี 10 หลักตามเดิม ไม่มี OTP หรือการเข้าสู่ระบบเพิ่ม
