# slip-lpsec — กฎการทำงานและข้อกำหนดหลัก
ปรับปรุง: 17 ตุลาคม 2569

## หลักฐานและการทำงาน
- ใช้สถานะ GitHub, CI, Vercel และ Supabase ที่ตรวจสดในรอบงาน ไม่ใช้ SHA เก่าจากบทสนทนาแทนหลักฐานปัจจุบัน
- อ่าน `AGENTS.md` และเกณฑ์ตรวจรับก่อนแก้ไข ประเมินผลกระทบและ Dependency ร่วมกัน
- งานอิสระตรวจแบบขนานได้ การแก้ Branch ต้องทำแบบลำดับและใช้ expected HEAD ห้าม Force Push
- เก็บการแก้ไขที่สัมพันธ์กันเป็น Commit เดียว แล้วทดสอบตรงกับ SHA จริง หาก CI ล้มเหลวต้องอ่าน Logs และแก้ที่สาเหตุ
- ไม่มีสิทธิ์ Merge Main, Deploy Production, เปลี่ยน Production SQL/RLS/GRANT/Storage หรือรหัสลับโดยไม่มีการอนุมัติแยกครั้ง
- CI ใช้บุคลากรและสลิปสมมติเท่านั้น ห้ามข้อมูลจริง เลขบัญชีจริง ไฟล์ทะเบียนจริง หรือ Secret ใน GitHub/CI/Logs/Chat

## ข้อกำหนดที่ยืนยันแล้ว
- ครูค้นหาโดยเลขบัญชีธนาคาร **10 หลักเท่านั้น** ไม่เพิ่ม OTP หรือ Login; การทราบเลขบัญชีของผู้อื่นยังเป็นความเสี่ยงที่ต้องแจ้งผู้ดูแล
- ผู้ดูแลใช้รหัสผ่าน Session ที่ลงลายเซ็นและการตรวจ Origin ตามระบบใหม่
- ทะเบียน CSV ในเครื่อง Admin มีคอลัมน์ 1 ชื่อ–สกุล, 3 เลขบัญชี, 4 เลขตำแหน่ง 7 หลัก; CSV ต้นฉบับไม่ออกจากเบราว์เซอร์
- PDF แบบ A มีหนึ่งสลิป/หน้า และ B มีสองสลิป/หน้า; หากจำนวนคี่อนุญาตหนึ่งสลิปเฉพาะหน้าสุดท้าย
- ต้องตรวจชื่อ เลขบัญชี เลขตำแหน่งให้เป็นบุคคลเดียวกัน **และเดือน–ปีที่พิมพ์ในแต่ละสลิปต้องตรงกับ Admin เลือก**; ผิดหนึ่งรายการต้องหยุดทั้งไฟล์ก่อน Stage
- แยกไฟล์ PDF ด้วยการ Render ภาพใหม่สำหรับแต่ละคน ไม่เก็บข้อความหรือ Resource ของอีกคน
- ห้ามเขียนทับเดือนที่ Publish แล้ว ข้อมูล Stage ยังเปิดให้ครูไม่ได้; การลบหรือกู้ข้อมูลค้างต้องใช้ Snapshot/ยืนยัน/Backup ตามเงื่อนไข
- LINE แจ้งเตือนเฉพาะเมื่อเลือกและ Publish สำเร็จ; LINE ผิดพลาดไม่ทำให้ผล Publish กลับเป็นล้มเหลว
- ปริมาณข้อมูลคาดว่าไม่เกิน 100 รายการ; รักษาข้อจำกัดป้องกันการ Stage เกินความสามารถ Publish ไว้
- ห้ามทิ้งไฟล์ Storage เดิมที่ยังไม่สามารถระบุหน้าที่ได้ รวมถึง 3 รายการที่ไม่มีประวัติอ้างอิง

## ความปลอดภัย / สิทธิ์การดำเนินการ
- ทำอัตโนมัติได้: อ่านสถานะ, ตรวจ Metadata Read-only, ปรับ Source บน Branch ทดสอบ, Unit/Static/Mock E2E, SQL สมมติใน Test ที่ Rollback และตรวจไม่เหลือข้อมูล
- ทำในเครื่องส่วนตัวที่ได้รับอนุญาต: ตรวจ PDF จริงด้วย PDF.js, Full-stack กับ Supabase Test ด้วย Test-only Credentials, Backup และ Restore Database + Storage จริง
- ต้องได้รับอนุมัติแยก: Merge/Deploy Production, เปลี่ยนสิทธิ์/Storage/Database จริง, คำสั่งทำลายข้อมูล, เปลี่ยนข้อกำหนดเจ้าของสลิป
- แยกหลักฐาน CI Mock, SQL Test Rollback, REST Test จริง, PDF จริง, Restore จริง และ Production Acceptance ชัดเจน ห้ามใช้ผลของระดับหนึ่งแทนอีกระดับ
